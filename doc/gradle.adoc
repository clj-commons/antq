= Working with Gradle

WARNING: Gradle support is experimental

== How it works

A `build.gradle` file is a program, so antq does not parse it.
Instead, antq runs Gradle in the project directory with a small init script, passed with `--init-script`.
The build's files are not changed.
For that Gradle run, the script adds a read-only task to each project that lists the project's repositories and declared dependencies.

All projects of a multi-module build are read in one run.
In a subproject's directory, antq reads that project and its subprojects.
Builds that use the Kotlin DSL (`build.gradle.kts`) are read the same way.

[IMPORTANT]
====
Running Gradle is riskier than parsing a file.
Gradle runs the build's scripts and plugins, and the Gradle wrapper may download a Gradle distribution.
Only run antq on Gradle projects you trust, as you would only run `./gradlew build` on projects you trust.

As such, checking Gradle dependencies is opt-in via `--check-gradle`.
====

== Requirements

* The project's Gradle wrapper (`gradlew`, or `gradlew.bat` on Windows) is used when there is one.
  It is looked up in the project directory and in its parent directories that belong to the same Gradle build.
  A wrapper that is not executable is reported as an error.
* Otherwise the `gradle` command must be installed.
* Gradle 8 or later.
* If Gradle cannot be run or fails, antq stops with an error that includes Gradle's output.

== Quick start

antq does not need to be added to the build.
Run it in the project directory as for any other project, e.g. as a https://clojure.org/reference/clojure_cli#tools[Clojure CLI tool]:

[source,sh]
----
clojure -Tantq outdated
----

== Repositories

antq looks up the latest versions in the repositories of each project, including those declared in `settings.gradle`, and in its default repositories, Maven Central and Clojars.
No changes to the build are needed.
(The `antq_list_repositories` task that earlier versions of antq used is no longer needed. A build that still has it keeps working.)

For a repository that needs a login, antq reads the credentials from `~/.m2/settings.xml`, like Maven and the Clojure CLI.
The `<server>` id must be the repository's `name` in `build.gradle`:

[source,groovy]
----
repositories {
  maven {
    name = 'company'
    url = 'https://repo.example.com/maven'
    credentials(PasswordCredentials)
  }
}
----

[source,xml]
----
<settings>
  <servers>
    <server>
      <id>company</id>
      <username>...</username>
      <password>...</password>
    </server>
  </servers>
</settings>
----

A Gradle plugin that reads Maven's `settings.xml` lets Gradle use the same entry.

== Running antq from the build

If you prefer `./gradlew outdated`, antq can also run from the build.
A dedicated configuration keeps antq off your application's classpath:

[source,groovy]
----
repositories {
  mavenCentral()
  maven {
    name = 'clojars'
    url = 'https://repo.clojars.org'
  }
}

configurations {
  antq {
    canBeConsumed = false
    canBeResolved = true
  }
}

dependencies {
  antq 'com.github.liquidz:antq:latest.release'
}

tasks.register('outdated', JavaExec) {
  classpath = configurations.antq
  mainClass = 'clojure.main'
  args = ['-m', 'antq.core', '--exclude=com.github.liquidz/antq']
}
----

antq exits with `1` when it finds outdated dependencies, so the task then ends as failed.
Add `ignoreExitValue = true` to the task if you do not want that.

== Limitations

* `--upgrade` is not supported.
* Dependencies that a plugin declares itself are listed too, e.g. the `nrepl` dependency of the `dev.clojurephant.clojure` plugin.
* Versions of Gradle plugins (the `plugins { }` block) are not checked.
* Dynamic versions such as `latest.release` or `3.+` are shown as they are written, and always reported as outdated.
  Use `--exclude` for them.

== Troubleshooting

* `Gradle wrapper is not executable`: run `chmod +x gradlew`.
* Gradle 9 needs Java 17 or later to run.
